# Cowork file sync: outcomes and failure modes (2026-11-06)

Scope: workspace/file sync for coding agents across Windows main, Ubuntu GPU box, Windows laptop, and small China cloud VMs; machines may be offline for days. Searches: WebSearch, WebFetch on primary docs, gh. Exa fetch failed (no EXA_API_KEY), so LayerFS was read with WebFetch. Items marked **[unverified]** rest on a single secondary source or an anecdote.

## Lessons for our design

- **Git is the sync layer for code.** Machines exchange commits through a remote; never replicate `.git` or a live working tree with Syncthing, Dropbox or iCloud (lock files and partial uploads corrupt repos).
- **One writer per branch.** Each agent gets its own worktree or LayerFS workspace on its machine and its own branch; cross-machine handoff is push/fetch. Serialize merges to main behind tests.
- **Make conflict policy explicit.** Refuse same-file conflicts by default (LayerFS `Conflict`), allow last-writer-wins only for named files (`.lww`), and never let an agent whole-file-overwrite a file a human has open.
- **Do not put the agent workspace on a network mount.** sshfs and rclone mount are slow for small files and unsafe for concurrent writers. Run the agent on the host that holds the code; use VS Code Remote-SSH for human editing.
- **Offline tolerance comes from local clones.** Each machine keeps a full clone and reconciles on reconnect, so days offline cost nothing. Mutagen/Syncthing sessions stall while a peer is down.
- **Auto-commit only to agent branches,** with a big-diff guard and a dry run. Never auto-push to main. Real-time CRDT co-editing is a later phase, and benchmarks must be measured on our own boxes (Windows is the gap for AgentFS and most FUSE stacks).

Unverified or weak items to re-check before acting: AgentRoom results; Mutagen sync reconnect interval; sshfs numbers (2012-2017); LayerFS benchmarks are self-reported on 1.0.0; Syncthing sync-conflict file naming; rsync row not fetched from a primary source.
